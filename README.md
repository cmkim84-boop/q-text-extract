# Q 텍스트 추출

보도자료 문서(PDF·HWPX·HWP)에서는 **원본 글을 그대로** 꺼내고, 이미지(캡처·스크린샷·사진)는 글자 인식(OCR)으로 읽어 복사할 수 있는 글로 바꿔 주는 윈도우 업무 프로그램. Q 시리즈(Q 이미지 편집기, Q 수치 계산기)와 같은 다크 에디터 톤이고 포인트 컬러만 민트(#1fc98e)다.

## 동작 방식 (v1.1)
- **문서(PDF · HWPX · HWP)**: 파일 안에 들어 있는 글을 그대로 읽는다. OCR 이 아니라서 숫자가 틀릴 일이 없다. 쪽번호("- 1 -")는 빼고, 줄 끝에서 끊긴 문장은 이어 붙인다. 표는 줄마다 칸을 탭으로 구분해 나온다.
  - HWPX 가 가장 깔끔하고, PDF 는 15쪽 기준 약 10초 걸린다(쪽이 많으면 더 오래).
  - 구형 HWP 는 표·글상자 안의 글이 빠질 수 있어 안내 문구가 뜬다. 한글에서 HWPX 나 PDF 로 저장해 열면 더 정확하다.
  - 글자 정보가 없는 스캔 PDF 는 "스캔 문서" 안내가 뜬다. 화면을 캡처해 이미지로 열면 된다.
- **이미지**: 아래 OCR 방식. 숫자·고유명사가 틀릴 수 있어 결과 위에 항상 대조 안내가 뜬다.

### 이미지(OCR) 쪽
- 글자 인식은 **윈도우에 내장된 OCR(Windows.Media.Ocr)** 을 쓴다. 인터넷 연결이 필요 없고 설치 파일이 커지지 않는다.
- 이 PC에 한국어 OCR 기능이 설치되어 있어야 한다. (설정 → 시간 및 언어 → 언어 및 지역 → 한국어 → 언어 옵션 → 광학 문자 인식)
- 파일 열기 / 끌어다 놓기 / Ctrl+V 붙여넣기(이미지) → 자동 인식 → 결과 글을 바로 고치고 복사(Ctrl+Shift+C) 또는 txt 저장(Ctrl+S).
- 이미지 위를 드래그하면 그 영역만 다시 읽는다. (우클릭/Esc 로 전체 영역)
- 정리 옵션: 줄바꿈 정리(문단 안 줄바꿈 제거), 공백 정리, 숫자 강조(숫자+단위를 색으로 표시해 원본과 대조).

### AI 기사 초안 (v1.2.0, 개인용)
- `기사 초안 → AI` 버튼: 추출한 글을 Claude API 로 보내 아주뉴스 지침(prompts 폴더)에 맞춘 기사 초안을 받는다. 결과는 **국문 초안 / 영문 초안 / 분류·검증 / 제목 3안** 탭으로 나뉘고, 탭마다 복사·txt 저장이 된다.
- 처음에는 `AI 설정`에서 내 API 키를 넣는다. 키는 이 PC(레지스트리)에 **암호화 없이** 저장된다. 환경 변수 `ANTHROPIC_API_KEY` 가 있으면 그것도 쓴다.
- 모델은 설정에서 고른다(기본 Claude Haiku 5.5, 비교용으로 Haiku 4.5·Sonnet 5.5 선택 가능). 호출이 끝나면 아래 상태줄에 **입력·출력 토큰 수와 예상 비용(원)** 이 나오고, 같은 내용이 `%APPDATA%\QTextExtract\ai_usage.csv` 에 한 줄씩 쌓인다. 비용 단가는 `aidraft.py` 의 `PRICES` 표(100만 토큰당 달러)를 기준으로 하니 공식 가격표와 다르면 그 표를 고친다. 환율은 설정에서 바꾼다.
- 지침 파일: `prompts/core`(핵심 4개), `prompts/extra`(스타일북·초안 지침 3개). 설정의 `지침 폴더 열기`를 누르면 내 계정 폴더로 복사본이 만들어지고, 이후에는 그 폴더의 파일을 쓴다. 스킬이 바뀌면 그 폴더의 `.md` 만 바꿔 넣으면 된다. 기본값으로 되돌리려면 그 폴더를 지운다.
- 원문이 외부(Anthropic API)로 전송된다. 엠바고 자료는 회사 정책을 확인할 것. 지침 파일은 회사 스킬에서 가져온 것이므로 이 프로그램은 외부에 배포하지 않는다.
- 실제 API 호출은 개발 환경에서 키 없이 시험하지 못했다. 시험은 가짜 응답으로 했으니 처음 한 건은 직접 확인한다.

## 파일
| 파일 | 역할 |
|---|---|
| app.py | 화면과 동작 |
| docextract.py | PDF·HWPX·HWP 원본 글 읽기 (빌드 후 자동 점검에도 포함) |
| aidraft.py | AI 기사 초안: 지침 읽기, API 호출, 응답 나누기, 토큰·비용 계산, 사용 기록 |
| aiui.py | AI 설정 창, 처리 방식 선택 창, 백그라운드 호출 |
| prompts/ | 아주뉴스 지침 파일(.md) — core 4개, extra 3개 |
| ocr_engine.py | 글자 인식 (윈도우 OCR, 개발용 대체 엔진, 빌드 후 자동 점검 `--selftest`) |
| textops.py | 줄 → 문단 정리, 공백 정리, 숫자 위치 찾기 (tests/ 에서 시험) |
| style.py | 색과 스타일시트 |
| feedback.py | 종료 때 의견 팝업 (Q 이미지 편집기와 같은 방식) |
| feedback_apps_script.gs | 의견 받는 구글 시트 코드 ('프로그램' 열 추가본) |
| installer.iss, build.bat, .github/workflows | 설치 파일 만들기 |

## 설치 파일 만들기
GitHub 에 올리고 Actions 의 `Build Windows installer` 를 실행하면 `QTextExtract-Setup.exe` 가 만들어진다. 이 과정에서 묶인 프로그램의 OCR·PDF·HWPX 읽기 부품이 실제로 도는지 점검하고(로그에 `RESULT: PASS`), 실패하면 설치 파일을 만들지 않는다.
내 PC 에서는 `build.bat` 을 실행한다.

## 개발용 실행
`python app.py` — 윈도우가 아닌 환경에서는 pytesseract 로 대신 읽는다(화면 확인용, 정확도 기준 아님).
